## 零、分层结论总览

| 发现 | 能否架构级一网打尽 | 说明 |
|------|--------------------|------|
| F1 SM2 MT 随机数 | ❌ 只能插件级 | RNG 发生在算法内部，框架无法外部接管；但 SDK 可降低再犯概率 |
| F2 无声截断（5 个 GCM 插件） | ✅ **架构级** | 内容 AEAD 层下沉 SDK 共享模块，AAD 绑定元数据，一处修复全覆盖、未来插件默认正确 |
| F3 SM2 C1 不校验 | ❌ 只能插件级 | 并入 SM2 插件重写 |
| F4 KDF 弱 + 无口令策略 | ✅ 半架构级 | GUI 口令策略对所有密码插件一次生效；KDF 参数自描述化后提默认值不破旧文件 |
| F5 流插件无认证 | ✅ 半架构级 | `authenticated` 属性声明 + GUI 警告是框架的；MAC 尾巴落在两个插件上 |
| F7 内存残留 | ✅ **架构级** | 每任务子进程是唯一能覆盖第三方库内部副本的方案（ECC DER 残留无进程内解法） |
| F6 低危项 | 文档/上游 | — |

原则：**安全关键的正确性逻辑只写一遍**（AAD 绑定、KDF 自描述、口令策略、进程边界），
插件只做算法差异；插件作者"想写错都难"才是收敛的完成态。

## 一、P0 — SM2 插件重写（F1 + F3 + F7 的 SM2 部分）

单个插件级大修，解决三项发现的交集，**不依赖任何架构改动，先行落地**：

1. **随机数全接管**：
   - 私钥：`os.urandom(32)` 拒绝采样到 `[1, n-1]`；
   - 加密临时 k：同样 `os.urandom` 拒绝采样。**不再调用 gmssl 的
     `encrypt()/decrypt()`**（其内部 `func.random_hex` 为 MT19937，已证实）。
2. **自实现 SM2 加解密尾段**（只复用 gmssl 的 `default_ecc_table` 曲线参数，
   不再依赖 `_kg` 私有 API）：
   - 点运算（加/倍/标量乘）在插件内实现，全程 `int`/`bytes`；
   - 加密：`C1 = kG`，`t = KDF(SM3, x2‖y2, klen)`，`C2 = M ⊕ t`，
     `C3 = SM3(x2‖M‖y2)`，密文 `C1‖C3‖C2`（保持现有容器布局不变）；
   - 解密：先做 **C1 曲线校验**（`0 ≤ x,y < p` 且 `y² ≡ x³−3x+b (mod p)`，
     不通过直接 `IntegrityError`——修 F3），再做点乘、KDF、XOR，**并校验 C3**
     （gmssl 原实现跳过了 C3 校验，我们补上后连现有 SM3(CEK) 辅助校验都可简化）；
   - 常数时间不追求（F6：本地 GUI，无远程计时面；文档注明）。
3. **消灭 hex 字符串副本**（F7 的 SM2 CEK 残留）：全程 bytes/bytearray，
   KDF 输入直接拼字节，结束统一 `secure_zero`。
4. gmssl 内部异常全部包装成干净的 `IntegrityError`/`WrongPasswordError`。
5. **否决的替代方案**：monkey-patch `gmssl.func.random_hex`（实测可生效，因为
   `sm2.py` 以属性访问调用）——但只修 F1 不修 F3/F7，且上游升级即静默失效，
   不采用。

验收：重放 `attack_lab/a3_mt.py`（预测私钥应失败）、`a4_invalid_curve.py`
（伪造 C1 应被拒）、现有 test_roundtrip 的 SM2 用例全部保持通过。

## 二、P1 — 架构级 A：内容 AEAD 层下沉 SDK（F2 的一网打尽）

新增 `encryptor/aead.py`（经 sdk re-export），提供唯一的分块认证加密实现：

1. **AAD 绑定**：每个 GCM 块的 AAD = `H(版本 ‖ 插件id ‖ 全部元数据)`。
   任何对总长/salt/nonce_prefix/wrapped-CEK 的改写、头部插件 id 交换，
   都在第一块即认证失败——无声截断通道被彻底关闭；
2. **KDF 参数自描述**：迭代次数等参数写入元数据（版本字节区分新旧），
   默认值提升不再破坏旧文件（旧格式回退：AAD=None + 旧迭代常量）；
3. **元数据版本字节**：v2 起元数据首字节为版本，旧文件无版本字节走 legacy 路径。

5 个 GCM 插件（aes/sm4/rsa/ecdh/sm2）删除各自的分块循环，换用该模块。
**效果**：F2 一处修复全覆盖；未来插件作者只要用共享层就默认正确，
"忘了绑 AAD"这类错误从结构上不可能发生。

验收：重放 `attack_lab/a5_integrity.py`（截断应报错）；新增专项测试：
改写 trailer 任一字段、交换头部 id、删除尾部块不改总长（旧路径已检测）。

## 三、P1 — 架构级 B：每任务子进程 JobRunner（F7 的一网打尽）

按既定方案落地上一轮讨论的进程隔离（A 层先行，B 层可选）：

1. 引擎层新增 `JobRunner` 抽象：进程内直跑（测试/CLI 用）/ 子进程包裹（GUI 用）；
   GUI 与插件接口零改动；
2. **旁路清单同步搬迁**（隔离成立的充要条件）：
   - `generate_keypair` → 子进程执行，父进程只收两个文件路径；
   - `describe_credential` → 子进程执行只回传字符串（或降级为仅描述公钥）；
   - 任务规格（口令/密钥路径）经管道传递，结果经文件系统交接；
3. 红利：崩溃隔离、取消 = 直接终止子进程；
4. 可选 B 层：子进程退出前自清洗（VirtualQuery 遍历私有可写区域 memset 后
   `os._exit`），压掉休眠/冷启动读取 RAM 残留的窗口；
5. **明确不覆盖**（文档升级为警告）：pagefile/hibernation/文件缓存/崩溃转储，
   OS 层缓解（加密页面文件、关休眠、全盘加密）。

验收：重放 `attack_lab/a7_memdump.py`——GUI 父进程存活期间镜像中
ECC 私钥/SM2 CEK/口令应 0 命中（子进程退出后无从 dump）。

## 四、P2 — 口令与教学插件（F4/F5）

1. **GUI 口令策略**（框架半，一次生效）：`_validate` 增加最小长度（8）与
   常见弱口令检查，弱口令警告需用户确认；插件可声明更高下限；
2. **KDF 默认迭代**（插件半，因 §二 的自描述化而不破兼容）：aes/sm4 → 600k
   （OWASP 2023），xor/sm3 → 600k（教学插件慢些无妨）；Argon2id 列为可选依赖项；
3. **教学插件加 keyed MAC 尾巴**（插件半）：`HMAC(派生密钥, 密文‖插件id)`，
   同时解决比特翻转、id 交换、错口令静默乱码三个问题。
   注：不用非密钥校验和（检测不了错口令）；keyed MAC 不会实质放大离线爆破
   （盐公开，攻击者本可对 KDF 离线猜）；
4. **插件安全属性声明**（框架半）：`authenticated: bool` + `security_note`，
   GUI 在选择无认证/教学插件时显示醒目警告——未来任何弱插件都自动被标注。

## 六、实施顺序与兼容性

```
P0  sm2 重写（独立，立即）
P1a aead.py + 版本化元数据        ← 兼容层先行，是 P2 提参数的前提
P1b 5 插件接入 aead.py
P1c JobRunner 子进程 + 旁路搬迁
P2  口令策略 / 600k / MAC 尾巴 / authenticated 声明
P3  文档与上游
```

兼容性红线：每个阶段结束后，`tests/` 三套 + attack_lab 全量重放必须通过；
旧 `.encx` 全程可解（legacy 回退路径有专项测试）。

## 七、风险与残余

- 子进程 spawn 每任务约 0.1–0.3s 启动开销（人工操作场景可接受）；
- 纯 Python SM2 点乘性能与 gmssl 相当（~10–20ms/文件，无感）；
- F7 中 str 口令在**子进程存活期间**仍可被 dump——进程模型只能保证
  "任务结束即不可达"，不能做到"从未存在"；这是 Python 生态硬边界；
- 教学插件即使加了 MAC，其机密性上限仍低（审计 F4），GUI 警告是主防线。
