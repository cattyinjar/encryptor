# `.encx` 容器格式说明（v1）

`.encx` 是本软件加密文件的统一容器格式。框架负责容器结构，插件只处理
"纯密文区间"和自己的元数据。

## 整体布局（多字节整数一律小端序）

```
+----------+-----------+------------------------+-------------------+---------------------+------------------+
| 偏移     | 长度      | 内容                   | 说明              |
+----------+-----------+------------------------+-------------------+---------------------+------------------+
| 0        | 4         | b"ENCX"                | 魔数              |
| 4        | 1         | 0x01                   | 容器版本 = 1      |
| 5        | 2         | uint16 N               | 插件 id 字节长度  |
| 7        | N         | 插件 id（UTF-8）       | 如 "aes-256-gcm"  |
| 7+N      | 变长 P    | 密文载荷               | 插件产生的密文    |
| 7+N+P    | 变长 M    | 插件元数据             | 加密时插件返回值  |
| 末尾 4   | 4         | uint32 M               | 元数据字节长度    |
+----------+-----------+------------------------+-------------------+---------------------+------------------+
```

- 密文长度 `P` = 文件大小 − (7+N) − (4+M)，无需显式存储；
- 元数据放在**尾部**（trailer）而不是头部：加密是流式的，盐/标签等往往要
  等全部密文写完才能确定；
- 解密流程：校验魔数与版本 → 读头部插件 id 定位插件 → 从文件末尾读出
  `M` 与元数据 → 把 `[7+N, 7+N+P)` 区间交给插件。

## 设计要点

| 需求 | 实现方式 |
|------|----------|
| 任意类型文件 | 容器完全不关心内容，按字节流处理 |
| 自有扩展名 | 加密输出统一 `原名.encx`；解密输出默认去掉 `.encx` |
| 算法可插拔 | 头部记录插件 id，解密时自动路由到对应插件；插件缺失时明确报错 |
| 元数据自定义 | trailer 中的 M 字节由插件独占使用（盐、nonce、标签、长度……） |

## 完整性保障

容器本身不提供校验和——防篡改/防截断/错密码检测是**插件**的职责
（例如 aes-256-gcm 插件用逐块 GCM 认证标签 + 明文总长度校验实现）。
容器只保证结构可解析、损坏时给出清晰错误。

## 兼容性策略

未来若出现 v2 等新版本，旧软件读取时会报"不支持的容器版本"，新软件
按版本号分派解析逻辑；插件 id 与元数据格式由各插件自行演进（建议在
元数据中预留版本字段）。
